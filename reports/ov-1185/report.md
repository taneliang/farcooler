# ov-1185 — local landing gate

The local wrapper now enables `lane-gate.py --landing --keep-target`. Plain
lane-gate and CI retain their existing full checks. No workflow was changed.

`reports/ov-1110/historical-gate.txt` ran through the production scheduler:

[Every step before/after](step-timings.md), [raw replay events](replay.json),
and [reproduction script](replay.py) are included. Run
`python3 reports/ov-1185/replay.py` to reproduce. The replay uses recorded
step seconds scaled by 0.01 and real threads through `landing_policy.run`;
the JSON includes actual elapsed seconds and the scale. All three runs use
the same historical input. They are **not three independent observations** of
current end-to-end gate performance.

The replay retains the historical full 665-second workspace nextest step;
there is no guessed saving from changed-crate selection or warm artifacts.
It schedules Clippy separately from Rust test setup/execution, starts long
families first, and leaves release bundle assembly and its dependent bundle
checks to CI. Apple jobs remain serial because they share SwiftPM products.
Four families run at most, under the gate's existing machine-wide lock.

**Limit:** the replay demonstrates a sub-15-minute schedule for the captured
workload, not a verified sub-15-minute median at today's typical load. It
excludes queue/unlock/load waits, Cargo build-lock contention, simultaneous
CPU/memory pressure, and CI steps added since the historical capture. A fresh
three-gate observation is still needed to close that part of acceptance 1.
The source capture itself predates Rust shadow mode; no shadow replay time
was added to the old baseline. No new full native builds were started for
this script-only change during the feature-build freeze.

## Rust selection and required checks

Landing reuses ov-1116's all-feature, all-target reverse dependency closure,
including dev/build/optional edges, cross-crate literal includes and the
CLI-to-daemon edge. It selects against a verified green main ancestor,
unioned with the requested base range and dirty/staged/untracked inputs.
Green candidates come from `CANDIDATES` NDJSON or successful main workflow
runs through `gh api`. Missing/failed evidence, offline metadata errors,
unknown inputs, manifests, fixtures, deletions and renames fall back to full.
The exact selection and reasons are written to `rust-selection.json` in the
step log directory.

Only default-host nextest receives a package expression. The leak wrappers,
CI nextest profile, failure propagation, feature checks, all Clippy variants,
doctests, Apple/Android suites and web checks remain. Landing removes the
shadow wrapper's redundant inventories/full-plus-selected measurement and
runs the required nextest command once. Full CI remains unchanged on both
Rust platforms. iOS UI smoke was already left to CI; this remains explicit.
Entitlement source checks still run locally without a stale signed bundle.

The gate waits for load before admitting its workers, retaining the outer
`heavy` queue and its five-minute load check. It does not stop another task.
Workers do not wait on load generated by their own gate. Each job gets private
`GITHUB_ENV`/`GITHUB_PATH` files and retains its exports between steps.
Lean target preparation/ceiling is applied once before parallel dispatch;
Rust lint/test workers use matching profiles and Cargo's artifact lock.
Landing keeps the target after success for the existing ov-1084 handoff.

## Failure proof and validation

`landing-policy-test.py` creates a real three-crate Cargo workspace and uses
real nextest processes through the gate's step runner and selection policy:

| Plant | Selected local command | Full workspace command used by CI |
| --- | --- | --- |
| Panic in affected reverse consumer | fails | covered by the unchanged full command |
| Panic in unrelated crate | passes | fails, naming `planted_unaffected` |

This is a real local execution of CI's full workspace command on a fixture,
not a claim that a hosted CI run was submitted. Independent tests verify
bounded overlap, Apple serialization, Clippy failure propagation, private
environment files, preserved exports, full fallback and retained checks.

Passed:

- `lane-gate.py --self-test` (including the six new policy tests).
- `rust-shadow-test.py` (the existing selector, inventory and failure tests).
- `gate-summary-check.py --self-test` and `heavy_lock.py --self-test`.
- `file-size-budget.py`, `bash -n scripts/landing-gate`, `git diff --check`.

The existing scratch-repository tests inherit global commit signing. Their
successful run used `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=commit.gpgsign
GIT_CONFIG_VALUE_0=false` for fixture commits only. The final branch commit
uses normal repository signing settings. Logs are retained alongside this
report.

The overlap regression test was also run with the production executor forced
to a single worker at its call site: it fails (the barrier cannot rendezvous).
[Red-run evidence](regression-red.log) is retained; the normal six-test run
passes. The wrapper dry-run also preserves PARTIAL labeling for `--only`.

The heavy-wrapper self-test and shell-wrapper dry-run used `/usr/bin` first
on PATH: this host's `/usr/local/bin/python3` cannot execute (Bad CPU type).
The initial heavy self-test failed for that interpreter mismatch; rerunning
with the system Python passed. No source change was needed for it.
