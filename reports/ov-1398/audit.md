# ov-1398 · Scripts, CI, and services pruning audit

## What this area must do

The Main workspace charter, “Goals” (owner, Nov 9), asks for (1) an orchestrator that configures, feeds, and supervises one workflow engine for all Far Cooler work and (2) less work to ship a change by reducing code and duplication, with feature logic in shared Rust and thin apps (R-112). The charter's “Workflow” paragraph names the coordinator's train as a temporary bridge. The Nov 21 ticket supplies the current single-engine requirement. The product jobs below come from [Jobs to Be Done](../../docs/jobs-to-be-done.md).

| Required responsibility | Requirement it serves |
| --- | --- |
| Run builds and checks as workflow steps, with affected-test selection, combined gate evidence, CI status, retry, and safe landing. | Goal 1. The orchestrator decides and supervises. Scripts can do bounded work on the engine's behalf. [Workflow scripts](../../docs/engine-script-rules.md) describes this interface. |
| Build, test, sign, publish, and serve supported releases and provide runner installation and upgrade paths. | Goals 1 and 2. Keep one tested route for getting a change to users and preserve compatibility with shipped clients. The owner uses these paths to Tend. |
| Keep relay account, enrollment, pairing, fleet pulse, notifications, and device trust working for the installed apps. | Reassure and Unblock on every surface, including notification taps, widgets, and watches. Enable the connectivity and identity needed for Capture, Decide, Drive, Review, and Tend. |
| Serve installation, public help, account and team management, and the handoff to apps and browser sessions. | Tend through downloads, sign-in, devices, and team and runner administration. Support the app jobs by keeping navigation and protocol handoffs reachable. |
| Keep shared service boundary code, wire contracts, fixtures, and tests wherever they protect those paths. | Goal 2. One implementation of shared service rules and evidence that app renderers agree with shared-core output. |
| Maintain current instructions and retain decision and release evidence with an identifiable consumer or retention purpose. | Both goals. The orchestrator and contributors need one current description of the path to shipped work. |
