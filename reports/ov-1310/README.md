# ov-1310: macOS runner acquisition

In [run 43938377995, attempt 1](https://github.com/taneliang/farcooler/actions/runs/43938377995/attempts/1), job 133553578699 (`Rust (macos-latest)`) had no runner or steps, from 19:28:27 to 19:43:29 UTC. Its GitHub check annotation says: “The job was not acquired by Runner of type hosted even after multiple attempts”, accompanied by a macOS arm64 capacity notice. GitHub's hosted runner acquisition service cancelled it; the annotation does not identify a repository setting or a configurable 15-minute limit. The job's execution timeout is 60 minutes in `.github/workflows/ci.yml`, and its matrix has fail-fast disabled. Do not attribute this to that timeout or claim a configurable GitHub setting without evidence.

`.github/workflows/ci-runner-retry.yml` listens for completed CI runs. For a main push, `scripts/ci-runner-retry.py` examines the latest instance of each Mac job across all attempts and selects cancellations without a runner or steps and with that exact annotation. It reserves one automatic retry per job name and run with a 90-day artifact, then requests the job rerun. Completion handlers for a run are serialized; subsequent handlers can recover other cancelled siblings. Prior manual reruns do not count as automatic retries. The reservation precedes the request, so a failed POST requires manual intervention; artifacts expire after 90 days. Test failures are not selected and test definitions are unchanged.

`scripts/ci-runner-retry-test.py` models both shards succeeding on attempt 1 and losing runner acquisition on attempt 2, executes the workflow's POST command against a recording `gh`, and verifies both requests and the once-only bound. GitHub's hosted acquisition service is external to this repository, so its cancellation code cannot be tested here; the automatic rerun has not yet been demonstrated on a live run.
