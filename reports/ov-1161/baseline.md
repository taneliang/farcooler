# ov-1161: CI cache baseline

Captured 14 November 2026 from the ten most recent completed main CI runs at the time of collection: [43542692133](https://github.com/taneliang/farcooler/actions/runs/43542692133), [43536261416](https://github.com/taneliang/farcooler/actions/runs/43536261416), [43525814763](https://github.com/taneliang/farcooler/actions/runs/43525814763), [43513781272](https://github.com/taneliang/farcooler/actions/runs/43513781272), [43498440945](https://github.com/taneliang/farcooler/actions/runs/43498440945), [43478975878](https://github.com/taneliang/farcooler/actions/runs/43478975878), [43455076891](https://github.com/taneliang/farcooler/actions/runs/43455076891), [43439314112](https://github.com/taneliang/farcooler/actions/runs/43439314112), [43417448416](https://github.com/taneliang/farcooler/actions/runs/43417448416), and [43410702134](https://github.com/taneliang/farcooler/actions/runs/43410702134). One newer run was still in progress. The second run was cancelled; the fifth failed overall, though its three jobs here succeeded. The last skipped both Swift jobs and has no macOS Rust job. Do not interpret a skip as a cache miss.

[baseline.json](baseline.json) contains every reported step's duration and conclusion for the macOS Rust and both Swift jobs, plus per-job cache outcomes. Durations are GitHub job API `completed_at - started_at`, in whole seconds; cancelled steps are included and are not complete timings. Cache outcomes come from `gh run view <id> --log`: a Rust hit requires the action's `Restored from cache key` line; a SwiftPM hit requires `Cache restored from key: swiftpm-`. The sample contains **9/9 Rust cache hits** in macOS Rust, **9/9 Rust and 9/9 SwiftPM hits** in each Swift job. These rates describe attempted restores, not ten independent builds, and do not prove all needed artifacts were present.

Across those nine attempts, median setup seconds were 12 for the Rust toolchain and 24 for Rust cache restore in macOS Rust; the Swift app job spent 11 on the toolchain, 19 on Rust restore and 26 on Go setup. The Swift test job spent 19 on Rust restore. Median full Rust test step was 1,798 seconds, including compilation and execution; its cancelled 482-second observation is incomplete. Median app bundle step was 1,126 seconds; median Mac test step was 1,162 seconds. The JSON retains the full distributions and all setup steps rather than attributing those totals to compilation.

The Rust action reports `cache-workspace-crates: false` in the logs. Thus a full cache key hit is not evidence that workspace outputs were restored; compilation after a hit is consistent with that configuration, but this sample does not quantify how much of the build is attributable to it. The jobs use different feature combinations, and Rust and Swift jobs have different build profiles. Any experiment retaining workspace outputs must isolate toolchain, target, profile and feature set, account for immutable exact-hit cache entries, and measure restore/save overhead as well as build time. SwiftPM currently caches downloads and checkouts, not compiled Swift outputs. Toolchain installation is duplicated across jobs but was small in this sample; merging jobs would change the critical path. Web's wasm tool tarballs and npm cache already have separate keyed caches in CI; their setup should be timed independently before changing them.

No cache or required-check behavior was changed in this capture. The workflow triggers only on main pushes and pull requests; this branch has no pull request. Two after-change branch runs and a validated cache change remain outstanding. A fair follow-up should run the same candidate twice on the branch, record both build and cache restore/save timings and outcomes, and compare against these main observations without treating the first cold population as a warm hit.
