# ov-879: Codex child transcripts

Codex children are discovered from native `thread_spawn` headers under the
joined parent's CODEX_HOME. Native thread UUIDs identify transcripts; unique
registered task paths are compatibility aliases. Guardian sources, unrelated
parents, ambiguous paths, unsafe file types and forks missing their native
history boundary are refused. Scoped readers revalidate the opened descriptor
on every poll. Child prose and calls remain in the child's projection.

The child's own model, ended/resumed state and launching parent turn populate
its summary. Its first own `parent_turn_id` preserves the launching turn's
ticket context; no ticket is guessed from a task path. Apple, Android and web
renderers display the model, including completed history.

## Completion pass — November 13

Independent review found two remaining gaps in the original implementation:
unavailable child files left stale running summaries, and web cards had no
transcript navigation. Both are fixed. A refused child binding retracts its
summary and running count; restoration rebuilds its own projection. A refused
drill also cannot republish nested child summaries.

The web now opens a separate read-only child transcript by native ID, scoped
on every page and follow through WASM and the existing client capability
checks. Closing, hiding, detaching or reconnecting disposes the child follower.
Child views have no composer or Stop. Labels come from the shared Rust words
table. A fresh review caught the reconnect case; the fix and shared-copy
relocation received a clean independent follow-up review.
