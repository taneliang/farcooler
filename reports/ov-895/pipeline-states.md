# ov-895: pipeline states match agent work

The projection mixed three independent facts: an agent's role selected the ticket's section, ticket stage age replaced the agent's reported activity, and the last agent card inherited the section's unassigned count. This implements the ticket's reviewed option B in the current Rust-owned projection, without changing producers, stale thresholds, workflow state, notification attribution, or CI aggregation.

## Projection contract

- The pipeline contains each eligible ticket ID once, in its own Building, Reviewing, Landing, or Needs You stage. Waiting, landed, dropped, unknown-stage, and known Done/Cancelled tickets are excluded. Needs You is an exclusive pipeline bucket; it is not inferred from stage age. `stuck` remains its internal wire/navigation identifier.
- Each stage counts unique tickets, with assigned plus unassigned membership equaling its total. Both the agent's assignment list and the line's open work records are evidence. Open assignments to absent agents remain assigned and say “not listed.” Missing evidence says “No listed assignee,” not “no agent running.” Closed or empty work records do not claim assignment.
- The separate roster contains each listed non-orchestrator agent ID once, including zero-ticket workers. Its assignment counts explicitly refer to pipeline tickets. A shared ticket can be assigned to several workers; that does not duplicate pipeline membership or claim simultaneous execution.
- Activity stays the runner's `doing_now`; title is separate identity. An empty activity falls back to “Runner reports working” or “No activity reported.” The working Boolean is preserved, not synthesized into idle or blocked provenance. Ticket stage age stays ticket context. Explicit waiting/CI-failure landing phases and Needs You reasons remain ticket context and cannot replace agent activity. Age-derived Stalled is not a liveness diagnosis.
- “Next landing” excludes known Done/Cancelled tickets using the same eligibility as the pipeline. Counts always state their units.

The Rust result drives the Mac, iPhone, and web renderers. Swift, Kotlin, and TypeScript decoders are regenerated from that result. Existing agent identity, activity, terminal navigation, ticket initiative, assignment, and timestamps remain available.

## Regression and UI evidence

The checked fixture `test/fixtures/plan-pipeline.json` is generated by the real Rust JSON bridge. It includes a builder assigned both building and review work, a zero-ticket reviewer, an active lander with an old stage timestamp, unassigned work in a staffed review stage, an absent assignee, and an explicit owner question.

[Phone-width capture](pipeline-360.png) and [desktop capture](pipeline-1440.png) show the actual web renderer over that fixture. The DOM check asserts visible rows, unique roster and ticket membership, assignment/total equality, accessible context, wrapping without horizontal overflow, and both 360/1440 widths. Hidden-shell captures were rejected and replaced after adding visibility assertions.

A separate read-only reviewer inspected the projection, regressions, and both visible screenshots. Review passed: zero-ticket reviewer retained; Reviewing has three tickets, two assigned and one unassigned; the builder's earlier ticket remains in Reviewing; absent assignment retained; active lander still says “Checking source CI” while the ticket separately shows three hours in stage. Findings about accessible context, desktop layout, agent title, empty assignment records, explicit landing phase, and next-landing eligibility were fixed. These screenshots establish web rendering, not native simulator execution.

The two principal regressions were proven red by temporarily reintroducing the removed behavior at the projection call site, then restoring the fix:

- Activity regression failed with actual `No move in 2 h`, expected `Checking source CI`.
- Membership regression failed when the agent inherited a nonzero section-wide `more` count.
