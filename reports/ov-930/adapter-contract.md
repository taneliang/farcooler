# ov-930 host contract (published before implementation)

Base: 7cae4421e9d2c3aae62ed06153c3f7f627267bd5. Exact ov-926 unique commits forwarded in order: db43f6393 -> 1502f74db, 26b1665ac -> 39dc7785c, 32a008112 -> ab557b5cf, b34e94d0d -> b736f1d89. No merge or rewrite.

Journals use the authenticated persistent Host.id / Host.runner_id, not a configured alias or phone-local runner UUID. Shared snapshots add `host` from Session.host; native bindings verify it against current host facts and browser binds it to the current WebRunner.

Each host adapter resolves its existing current authenticated core at EACH invocation; it does not connect, enroll, or retain a Session across awaits. A disconnected core is unavailable. Presentation comes only from workflow.snapshot.presentation. Entire selected Action is forwarded; native adapters derive no Intent, permission or command.

Implemented coordinated shared route: workflow.prepare_selection({workspace,item,action,revision: decimal string,epoch: decimal string}). It re-reads authenticated snapshot, preserves the exact observed revision/epoch and Action guard, returns read-only inspections before allocating any mutation identity; for commands it chooses the next sequence for the authenticated `wire:principal` source in Rust with checked overflow, generates one UUID and delegates to existing validation/mapping. workflow.prepare_action remains compatible. Decimal strings preserve max-u64 observations across JS. No caller capabilities/Grant.

Journal namespace is [account identity, actual host identity, workspace]. Journal entries retain item/run/action and opaque prepare result. Persist a preparing marker before prepare; persist the entire Prepared envelope before any submit. Write failure prevents submission. Keep envelopes and a persistent submission audit count across view closure, reconnect and process restoration, including after a discarded submit reply. Read/refresh/restore never submits. Explicit retry sends identical Prepared JSON through the current core; it never prepares again. Each explicit invocation sends at most one submit under the existing Session deadline; later explicit invocations may retry identical retained bytes without a lifetime ban. A versioned SHA256-checked journal validates explicit Preparing/Prepared/Complete/Abandoned phases. A lost prepare answer initially fails closed; a valid Preparing-only marker with zero attempts can explicitly re-read authenticated state and reset, with a subsequent fresh user selection required for a new intent. Corrupt/ambiguous journals cannot reset or infer that nothing was sent. Result attribution uses retained item/run, with reviewed renderer generation/selection fencing preserved.

Swift uses the same AgentKit adapter on Mac/iOS and atomic files in the application's own support directory; Android uses private app files; browser uses durable origin storage. Scratch verification injects private directories/storage. No owner app/data/profile is accessed by checks. Account switch cannot reuse a previous account's journal. Unsupported server/capability fails closed.

Browser snapshot parsing must preserve every integer token before Number conversion; identity decimal serialization never passes through Number. Actual browser checks must exercise decoding and the prepare route boundary with max-u64, not just WASM input bytes.
