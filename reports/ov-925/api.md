# Authenticated workflow command API v1

Capability `workflow_commands`. Additive protobuf `WorkflowCommand { uint32 schema; string json; }` request and `WorkflowReply { uint32 schema; string json; }` result, tags 640. Methods `workspace.set_workflow`, `workflow.enqueue`, `workflow.get`, `workflow.approve`, `workflow.cancel`, `workflow.review`. Target workspace UUID is the existing request envelope target. All require Control scope because raw workflow snapshots include definitions/operation settings.

JSON is a closed, schema-1 Rust command contract (published in `crates/protocol/src/workflow_commands.rs`). Mutations carry stable command id, expected workflow revision, epoch and source sequence. Publication additionally compares the current configuration pin. Enqueue selects an immutable definition pin, never a mutable current-definition lookup. Review supplies the exact observed evidence and accept/rework decision, never a newer evidence lookup. Approve/cancel carry the run and definition pin the caller observed. No principal, Grant, operation result, Observe or Resolve can be supplied. Principal is derived from existing authenticated caller admission.

Development construction only: explicit RpcFactory embedding supplies an isolated fixture runtime handle; ordinary daemon factories have no workflow runtime. No environment-selected production switch. Same command identity and content retry returns its durable receipt, independent of reply delivery, wall-clock time and subsequent state changes. Unsupported adapter settings are refused by the existing fixture boundary. This API does not promise real harness/MCP/GitHub provider execution.
