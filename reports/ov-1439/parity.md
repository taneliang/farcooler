## Browser boundaries

| Boundary | Product handling |
| --- | --- |
| B1 · Local files and clipboard. A page cannot enumerate arbitrary client paths, read Finder selections, or infer a runner path from a dropped file. | Use rooted Rust browse/search/read for runner paths, a user-selected file or drop/paste for client intake, upload bytes with limits, and keep path references explicit. Download for viewing externally. |
| B2 · Local services, tools, native apps and updates. A tab cannot spawn ssh/git/tmux, register services, launch arbitrary editors/Finder or install an update. | Install and start through a CLI/package/service. Let an authenticated core operate its own host under explicit scope. Use user-invoked editor URIs where configured and copy commands otherwise. Browser reload handles the frontend version. |
| B3 · Dragging. In-page drag and resize are feasible. Native window drag/placement and arbitrary cross-app file-path drops depend on OS permissions and browser payloads. | Use pointer and keyboard layout commands with touch fallbacks, browser-provided file drops only, and share layout intent across tabs. |
| B4 · Shortcuts and windows. A site cannot register OS-global shortcuts, reliably intercept browser-reserved commands or position/focus arbitrary windows. | Use scoped remappable bindings and a visible action palette, preserve terminal passthrough, and use OS launch/shortcut integration only if later needed. |
| B5 · Embedded sites. Pages can refuse framing, and cross-origin browsing is isolated. | Render a pane only for embed-compatible URLs. Offer regular external tabs for the rest. |
| B6 · Closed-tab notifications. A polling tab may suspend or close, and browser/OS settings govern delivery. Screen lock, system presence and native notification priority are platform-specific. | Start with in-page notices. Add server Web Push with a service worker, permission, minimal payloads, scoped dedup and exact-item deep links. Keep the board authoritative when delivery is unavailable. [W3C Push API](https://www.w3.org/TR/push-api/) |
| B7 · Direct runner access. A web page has browser networking and WebAuthn, with neither raw TCP/Unix socket access nor the user's SSH agent/config. | Keep remote passkey over Tailcat. Bootstrap via CLI, and use the authenticated local adapter below for local operation or an explicitly installed bridge for direct SSH. |

## How a browser reaches the core

**Remote today.** [The app Worker](../../services/web/src/api.ts) provides the versioned shell and WorkOS-backed account/session routes. The [relay](../../services/relay) handles device ceremony and optional encrypted recovery copies. The browser stores a device/node identity, creates a WebAuthn credential and offers its public key plus node key with a QR/short code. An enrolled device approves selected runners, authorizes the device with the runner, and returns granted runner routes and pinned host keys. The browser compares and keeps the grant. A supported passkey PRF can unlock a saved recovery copy. An account session or recovery record alone grants no runner access. See [app.ts](../../services/web/src/client/app.ts), [device.ts](../../services/web/src/client/device.ts) and [the web recovery notes](../../services/web/README.md).

Go/WASM Tailcat dials the granted node over its browser-compatible DERP transport. This data path is distinct from the account/ceremony relay. The runner listener reaches its loopback sshd. Rust/WASM verifies the pinned SSH host key and converts the browser passkey assertion into an OpenSSH security-key signature. SSH applies the runner's authorized-key scope and carries the Far Cooler wire session and pane channels through the runner’s stdio bridge to the daemon. The daemon owns replay and writer state. Reconnect may need another passkey touch. [Go/WASM Tailcat](../../crates/tailcat/go/main_js.go), [SSH](../../crates/web/src/ssh.rs), [WebAuthn mapping](../../crates/web/src/passkey.rs), [wire session](../../crates/web/src/wire.rs).

## Proposed ticket order

1. **Remote work creation and terminal recovery.** On an already paired runner, pick a workspace/repo, create or resume a worktree, start a shell/agent, rename and close it, recover a lost terminal, and see writer/read-only state. Reuse daemon methods and include basic stable workspace/terminal URLs. This removes the first reason to open Mac during a work session.
2. **Permanent orchestrator and workstation navigation.** Keep the workspace's orchestrator within reach with raw/chat switch and held drafts. Add a responsive main area and a minimal split with pane focus, command palette, and workflow back/forward. Reuse existing Plan/Needs You actions and secure reconnect. Preserve work across refresh and sleep.
3. **Board and end-to-end ticket work.** Add the workspace board, ticket create/edit/start, shared unread, agent and worktree links, then files and Changes review with inline comments/approvals and retained review position. Put Plan next to the orchestrator and add Engine station/ticket drill-down using the existing workflow actions. Take a ticket from creation through review and landing without leaving the browser.
4. **Remote continuity and cutover trial.** Complete ordinary runner health/reconnect, first-device bootstrap or account recovery via CLI, in-page attention and opted-in Web Push for daily interruptions. Trial one real day on a remote runner with the Mac app closed. Verify repo/worktree setup, switching across runners, agent start and recovery, responding to Needs You, diff/review and landing follow-through, including a reconnect and read-only refusal. Keep macOS in service through the trial and close any blockers it finds.
5. **Local mode on Linux, then Windows via WSL2.** Reuse the same workday suite with the same-origin loopback bridge, CLI/service bootstrap, no hosted account requirement, and isolated tmux. Verify offline start, restart/replay and browser access in both environments. Track a Windows-native broker separately if WSL2 cannot meet a required workflow.
6. **Finish remaining parity and remove native-only checks.** Complete runner/teammate administration, charter/steering and uncommon recovery, layout and shortcut polish, file/editor handoffs and the browser-specific substitutions above. Remove native-only checks and shipping work after the owner confirms the parity or substitution for each daily dependency, with core/transport checks still required.
