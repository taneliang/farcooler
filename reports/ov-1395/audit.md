# ov-1395 · Rust and protobuf pruning audit

Audited `705e8767c` on 2026-11-21. **152 net lines are safe to remove in four follow-up tickets. Another 6,620 counted lines depend on owner decisions.** The largest decision is whether to keep orchestrator-authored Pages. The coordinator train implementation is already gone from this scope. Its migration and compatibility code still has callers.

## What Rust and the wire must do

The Far Cooler Main workspace charter's **Goals** section (Nov 9, runner workspace ending `d7401571`) sets the order. **G1** is for the orchestrator to configure the workflow, plan, feed it and supervise it, with all Far Cooler work running through the engine and plain terminals available for the owner's scripts. **G2** is to reduce the work needed to ship a change by keeping feature logic once in shared Rust and making the apps thin renderers (R-112). The workspace charter is runner-held. The checked-in [jobs to be done](../../docs/jobs-to-be-done.md) supplies the surface requirements. The [pipeline design](../../docs/engine-pipeline.md) also describes planned work, so a design reference alone does not establish a production caller.

## A · Safe removal tickets, ranked

1. **Remove the detached theme-rank test source — 63 lines.** `crates/store/src/plan_rank_tests.rs` (63). `git show faba876f5 -- crates/store/src/plan.rs` shows the module declaration being removed during the line cutover. Searching for `plan_rank_tests`, `one_move_leaves_the_ranking_one_to_n` and `the_move_is_recorded_under_who_made_it` finds the two definitions and no include or harness entry. The file contributes zero current test coverage. Its subjects are still live via `rpc_plan.rs` → `Store::move_theme`. The old assertions on tied/gapped ranks and event attribution are worth considering when maintaining that test coverage.
2. **Reserve unsent snapshot and terminal frame fields — 40 net lines.** `proto/farcooler.proto:25–26` (2 → 1 at message scope), `:1162–1177` (16 → 3), `:1192–1195` (4 → 1 at message scope), `:1205–1223` (19 → 4), `crates/protocol/src/lib.rs:1232–1239` (8). Keep reservations for `WireEnvelope` 15–16, `TerminalFrame` 11–14, and all fields in the retired message scopes. Tracked source search for `SnapshotChunk|snapshot_chunk|TerminalInputAck|TerminalResizeFrame|FlowAck|Body::TerminalFrame|Kind::(InputAck|FlowAck|Resize)` finds schema definitions and baselines with no sender or receiver constructing these variants. Swift's same-named `TerminalInput` is a keyboard class. The current paths are request/response `terminal.write` / `terminal.resize` (`client/src/session.rs:921–932,978–986`), `terminal.attach` with `Event` output/gap frames (`daemon/src/resync.rs` → `client/src/session/link.rs`), and ordinary list RPCs plus events for fleet sync. The flow-ack constants and lease expiry constant occur only at their declarations. Preserve Event's terminal-frame arm, replay and backlog limits.
3. **Retire payload bodies for already-retired writes — 37 net lines.** `proto/farcooler.proto:6040–6074` (35 → 2) and `:3094–3098` (5 → 1). `git grep -nE 'LandingStart|LandingSet|StackSetParent'` has only proto declarations. `Request` and `Result` already reserve the old landing slots, and `Request` reserves the old stack-parent slot. `capability::RETIRED_METHODS` and `rpc.rs:718–719` still answer those names. The engine replaced landing writes in ov-960. `stack.get` still reports inferred stack parents. Keep `reserved 1 to 9` in each landing payload and `reserved 1 to 3` in the stack payload, and retain refusal coverage and baseline.
4. **Remove unused review caps and cache alias — 12 lines.** `crates/daemon/src/review.rs:434–440` (7), `crates/review/src/lib.rs:49–51` (3), and `crates/daemon/src/stack.rs:755–756` (2). A tracked whole-word search for `MAX_SNAPSHOT_BYTES_PER_WORKTREE|MAX_SNAPSHOT_BYTES|RepoId` returns exactly the three declarations. These definitions enforce no size limit and supply no cache key types to a caller. The actual diff limits in `review::limits` and UUID cache keys remain live.

**Section A total: 63 + 40 + 37 + 12 = 152 net lines.** The canary baseline contains the old message fields and reserved names. Keep the baseline and preserve message-scope reservations, even when there are no remaining Rust constructors.

## B · Working surfaces for owner decision, ranked

1. **Require a workflow for all ticket execution, including unconfigured workspaces? — 293 lines counted.** `crates/cli/src/tasks.rs:365–427,654–669` (79), `crates/cli/src/plan_agent_dispatch.rs:102–146,149–214` (111), `crates/daemon/src/agent_panes.rs:28–130` (103). ## Checked boundaries and uncertain work

- **Coordinator trains.** `git grep -l 'train\.sh' -- crates proto` returns no match. `cli/src/plan_tests.rs:821–837` rejects retired train and lane verbs. The daemon's retired-method table returns `MethodRetired` for `train.start` / `train.set`, and carries no live handler. `store/src/lane_migrations.rs` (283), `line_migration.rs` (699) and `line_migration_tests.rs` (403) are registered and exercised upgrade paths. That includes fresh schema creation through the registry and the supported pre-line cutover. The proto reservation shells at 6507–6566 and the compatibility responses have explicit consumers in lint and socket tests. Removing any of this needs a changed upgrade policy and a measured schema baseline; no lines counted. The shell coordinator flow outside `crates/` and `proto/` belongs to the scripts audit.
- **Unwired neutral pipeline — uncertain, 6,245 tracked lines examined.** In `crates/workflow`, `src/pipeline/` (2,049), `src/adapters/` (571), `src/migrate/` (600) and their matching coding/pipeline/migrate/differential tests, support and migration snapshot (3,025) form a separate implementation with tests. The daemon's similarly named `workflow_runtime/adapters.rs` is live and distinct. Searches for external `farcooler_workflow::pipeline`, `::adapters` or `::migrate` imports and for schema-3 publication found no product caller of the neutral implementation. [ov-1273](../ov-1273/README.md) records it as unwired; `docs/engine-pipeline.md` §10 plans the runtime switch and the migration is still maintained. Is schema 3 still the intended replacement? Deferring that project would lose tested general station/adapter semantics and migration/replay work. Landing it would make sections of the currently live engine candidates instead. Excluded from both sums pending that direction.
- **Engine cutover and old installations — uncertain.** `crates/cli/src/workflow_cutover.rs`, `crates/daemon/src/cutover_admin.rs`, `cutover_gate.rs` and `crates/store/src/engine_cutover/` serve shipped maintenance commands, daemon startup and writer exclusion. A completed handover on one runner doesn't establish that old stores or frozen attempts can no longer arrive. Retiring these would lose supported upgrade, recovery and authority checks. This needs an explicit supported floor, data inventory, rehearsal and a design that retains writer fencing. Old chat migration and `settings.set_projector`'s compatibility acknowledgment similarly still have startup or old-client callers.
- **Adjacent landing code is active.** `crates/daemon/src/landing.rs` and `landing_read.rs` read repository/branch facts, drive `repository.landing`, workspace settings and charter surveys, and run a periodic reader from daemon startup. Engine groups also use shared `Landing`, phase and CI structures. The file names alone do not identify the retired landing job.
- **Generic Operation wire surface — uncertain.** `proto/farcooler.proto:454,1010,2132–2151` (22 lines) declares the result/event and payloads. `git log -S "Operation operation_changed" -- proto/farcooler.proto` traces it to the workspace scaffold. No producer was found in the tracked tree. `client/src/session.rs:338` (1) turns `OperationChanged` into a fleet refresh, and `client/src/session/results.rs:25` (1) formats the result variant name. Do older or external runners send it? Retirement would lose that refresh and result diagnostic. Excluded pending evidence on that contract.
- **Other wire names with ambiguous evidence.** `BranchAgainst` has no typed sender hit, but `daemon/src/review_ops.rs:201` deliberately handles the selector, so it is an input contract. Handshake, declared capabilities, reserved tags, app bridge names generated from `wasm_bindgen(js_name = ...)`, and raw JSON dispatch strings require checking their actual consumers before pruning. Installed client versions and external protocol use remain unmeasured.
